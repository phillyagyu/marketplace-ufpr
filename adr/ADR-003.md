# ADR-003: Isolamento de Integrações Externas via Porta de Saída e Injeção de Dependência

## Status
Aceito

## Contexto
O sistema precisa notificar usuários sobre mudanças de status na contratação (RF08). O atributo de Modificabilidade (ASR-01) exige que o provedor de notificação (E-mail, WhatsApp, SMS) possa ser trocado sem afetar a lógica central. Além disso, as chamadas de rede para APIs externas não podem quebrar os testes automatizados ou impedir a execução local caso o computador esteja sem internet.

## Alternativas consideradas
1. **Chamada Direta:** Inserir a biblioteca de e-mail diretamente no Caso de Uso. Alto acoplamento e impossibilidade de testar sem rede.
2. **Fila de Notificações (Broker Assíncrono):** Melhora a tolerância a falhas, mas introduz um serviço externo (RabbitMQ/Kafka) que fere a restrição de execução simplificada (RES05).
3. **Porta de Saída (Outbound Port) Síncrona:** Criar uma interface abstrata e instanciar a ferramenta de envio via Injeção de Dependência.

## Decisão
Definir uma Porta de Saída abstrata chamada `NotificadorPort`. A camada de Aplicação dependerá apenas dessa interface (Princípio da Inversão de Dependência - DIP do SOLID). Criaremos adaptadores concretos (`EmailNotificador` para produção, e `NotificadorFake` para testes automatizados).

## Consequências
* **Benefícios:** Atende diretamente à Modificabilidade (ASR-01), aplicando o princípio Aberto/Fechado (OCP). Garante testes determinísticos e sem necessidade de conexão via `NotificadorFake`.
* **Custos e Limitações:** Como o processamento atual da interface é síncrono, uma latência excessiva no provedor de rede real (SMTP) causará um pequeno atraso na resposta da API para o usuário.
