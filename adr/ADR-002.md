# ADR-002: Persistência desacoplada via Modelo de Domínio Rico

## Contexto
O sistema possui regras de negócio críticas, como a proibição de auto-contratação e o bloqueio estrito de horários exclusivos. Validar essas regras no banco de dados ou no controlador impede testes isolados e acopla o domínio à infraestrutura.

## Alternativas consideradas
- Validação no controller ou no banco de dados (transaction script);
- Entidades atreladas ao framework de persistência (active record);
- Modelo de domínio rico integrado ao padrão repository.

## Decisão
Utilizar um modelo de domínio rico onde as entidades em memória validam as próprias regras de estado, delegando a gravação para abstrações de repositório (ex: `ServicoRepository`).

## Consequências
- Impossibilita a geração de estados inválidos antes da persistência;
- Viabiliza testes unitários ultrarrápidos independentes do banco;
- Exige esforço manual para mapear dados (data mapper) entre as entidades puras e as tabelas do SQLite.
