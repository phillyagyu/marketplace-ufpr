Visão Ponta a Ponta

1. Como o Código Funciona em Tempo de Execução?

De Fora para Dentro (Inversão de Dependência)

Quando alguém roda python -m src.main (ou clica em "Agendar Horário" no Front-end Web), a requisição atravessa as camadas seguindo exatamente esta sequência de 6 passos:

1

Bootstrap (src/main.py)

É o Composition Root: instancia o banco SQLite e o EmailNotificador e injeta-os dentro dos Casos de Uso pelo construtor.

2

Entrada (adapters/inbound)

O MarketplaceController (CLI) ou web_controller.py (HTTP) recebe o pedido do usuário e chama use_case.executar(...).

3

Orquestração (src/application)

O SolicitarContratacaoUseCase busca o serviço pela porta abstrata servico_repo.buscar_por_id().

4

Regras Puras (src/domain)

As entidades Servico e SlotDisponibilidade validam RES01 (auto-contratação) e RES02 (overbooking) em memória.

5

Persistência (adapters/outbound)

Se nenhuma exceção foi lançada, o caso de uso chama salvar() nos repositórios SQLite dentro de uma transação atômica with self.conn:.

6

Notificação (NotificadorPort)

Somente após gravar no banco com sucesso, o caso de uso chama notificador.notificar() (SMTP ou Fake).

2. Camada de Domínio (src/domain/)

Rich Domain Model • Information Expert & Creator (GRASP)

Esta é a camada mais importante do trabalho. Note que nos arquivos src/domain/entidades.py e src/domain/excecoes.py não existe nenhum import sqlite3, nem HTTP, nem JSON. O único motivo para esses arquivos mudarem (SRP - SOLID) é se uma regra de negócio da universidade mudar.

2.1 src/domain/excecoes.py Exceções Semânticas

Define a classe base ErroDominio(Exception) e 6 subclasses específicas que representam violações das regras do edital:

  • AutoContratacaoError → Protege a RES01 (prestador tentando contratar o próprio serviço).
  • SlotIndisponivelError → Protege a RES02 e ASR-02 (tentativa de overbooking em horário já reservado).
  • TransicaoEstadoInvalidaError → Impede avaliar antes de concluir, avaliar duas vezes ou cancelar contrato já concluído (RES03).
  • NotaInvalidaError → Impede nota fora de 1..5 ou comentário vazio (RES03).
  • PermissaoNegadaError → Garante que só o prestador conclua (RF06) e só o solicitante avalie (RF07).
  • IntervaloHorarioInvalidoError → Impede criar um slot com fim <= inicio.

2.2 SlotDisponibilidade e Servico Information Expert & Creator

Em vez de o Caso de Uso fazer if slot.status == LIVRE: (o que seria um Modelo Anêmico), a própria entidade protege seu estado:

class SlotDisponibilidade:
    def reservar(self) -> None:
        # Information Expert (GRASP): o Slot detém 'self.status',
        # logo ele mesmo valida e bloqueia overbooking (ASR-02)
        if not self.esta_livre():
            raise SlotIndisponivelError()
        self.status = StatusSlot.RESERVADO

class Servico:
    def adicionar_slot(self, inicio, fim) -> SlotDisponibilidade:
        # Creator (GRASP): Servico contém e agrega SlotDisponibilidade
        novo_slot = SlotDisponibilidade(f"slot-{len(self.slots)+1}", self.id, inicio, fim)
        self.slots.append(novo_slot)
        return novo_slot

    def validar_contratante(self, solicitante_id: str) -> None:
        # Information Expert (GRASP): Servico detém 'self.prestador_id' (RES01)
        if solicitante_id == self.prestador_id:
            raise AutoContratacaoError()

2.3 Contratacao e Avaliacao (src/domain/entidades.py) Raiz de Agregado & Creator GRASP

Por que ninguém instancia Avaliacao(...) solta no meio do sistema? Porque segundo a RES03, uma avaliação só pode existir vinculada a uma contratação real que já atingiu o estado CONCLUIDA. Por isso aplicamos o padrão Creator (GRASP) dentro de Contratacao.registrar_avaliacao(): 

class Contratacao:
    def concluir(self, usuario_id: Optional[str] = None) -> None:
        if usuario_id is not None and usuario_id != self.prestador_id:
            raise PermissaoNegadaError("Apenas o prestador responsável pode concluir (RF06).")
        if self.status != StatusContratacao.CONFIRMADA:
            raise TransicaoEstadoInvalidaError("Apenas contratações CONFIRMADAS podem ser concluídas.")
        self.status = StatusContratacao.CONCLUIDA

    def registrar_avaliacao(self, nota: int, comentario: str, solicitante_id: Optional[str] = None) -> Avaliacao:
        # 1. Valida se quem está avaliando é realmente o solicitante (RF07)
        if solicitante_id is not None and solicitante_id != self.solicitante_id:
            raise PermissaoNegadaError("Apenas o solicitante pode registrar avaliação (RF07).")
        # 2. Valida máquina de estados e unicidade da avaliação (RES03)
        if self.status != StatusContratacao.CONCLUIDA:
            raise TransicaoEstadoInvalidaError("A avaliação só pode ser registrada para contratações CONCLUÍDAS.")
        if self.avaliacao is not None:
            raise TransicaoEstadoInvalidaError("Esta contratação já possui uma avaliação registrada.")

        # 3. Creator (GRASP): Instancia Avaliacao (que por sua vez valida 1 <= nota <= 5 no __init__)
        self.avaliacao = Avaliacao(f"aval-{self.id}", self.id, nota, comentario)
        return self.avaliacao

3. Camada de Portas de Saída (src/ports/interfaces.py)

DIP & ISP (SOLID) • Indirection & Protected Variations (GRASP)

O que este arquivo faz?

Declara 3 classes base abstratas (abc.ABC) que funcionam como "tomadas" (Portas). Os Casos de Uso só enxergam essas 3 interfaces; eles não fazem ideia se os dados vêm de um dicionário em memória, de um arquivo SQLite ou de um servidor PostgreSQL.

  • Princípio da Segregação de Interfaces (ISP - SOLID): Em vez de criar uma interface gigante BancoDeDadosPort, separamos em 3 interfaces pequenas e coesas:
    • ServicoRepository (salvar, buscar_por_id, listar_disponiveis)
    • ContratacaoRepository (salvar, buscar_por_id, listar_por_usuario)
    • NotificadorPort (notificar(destinatario, assunto, mensagem))
  • Assim, o ConsultarServicosUseCase depende apenas de ServicoRepository!
from abc import ABC, abstractmethod
from src.domain.entidades import Contratacao, Servico

class ServicoRepository(ABC):
    @abstractmethod
    def salvar(self, servico: Servico) -> None: pass

    @abstractmethod
    def buscar_por_id(self, servico_id: str) -> Optional[Servico]: pass

    @abstractmethod
    def listar_disponiveis(self) -> List[Servico]: pass

class NotificadorPort(ABC):
    @abstractmethod
    def notificar(self, destinatario: str, assunto: str, mensagem: str) -> None:
        pass

4. Camada de Aplicação / Casos de Uso (src/application/casos_de_uso.py)

Controller (GRASP) • OCP & DIP (SOLID)

Os Casos de Uso recebem as Portas no construtor (Injeção de Dependência) e apenas coordenam a conversa entre os Repositórios, as Entidades de Domínio e o Notificador.

4.1 SolicitarContratacaoUseCase (Fatia Vertical de Mutação)

Observe como o método executar() bate linha por linha com o Diagrama de Sequência e com o Diagrama de Comunicação:

class SolicitarContratacaoUseCase:
    def __init__(self, servico_repo: ServicoRepository,
                 contratacao_repo: ContratacaoRepository,
                 notificador: NotificadorPort):
        # DIP (SOLID): recebe abstrações, nunca classes concretas!
        self.servico_repo = servico_repo
        self.contratacao_repo = contratacao_repo
        self.notificador = notificador

    def executar(self, servico_id: str, slot_id: str, solicitante_id: str) -> Contratacao:
        # Passo 1.2: Busca o serviço no repositório
        servico = self.servico_repo.buscar_por_id(servico_id)
        if servico is None:
            raise ErroDominio(f"Serviço '{servico_id}' não encontrado.")

        # Passo 1.3: Delega validação de auto-contratação (RES01) ao Domínio
        servico.validar_contratante(solicitante_id)

        # Passos 1.4 e 1.5: Busca o slot e reserva (protege ASR-02 / Anti-Overbooking)
        slot = servico.buscar_slot(slot_id)
        slot.reservar()

        # Passo 1.5.1: Instancia a contratação CONFIRMADA
        nova_contratacao = Contratacao(
            id=f"cont-{uuid4().hex[:8]}",
            servico_id=servico.id, slot_id=slot.id,
            solicitante_id=solicitante_id, prestador_id=servico.prestador_id
        )

        # Passos 1.6 e 1.7: Persiste o slot atualizado e a nova contratação
        self.servico_repo.salvar(servico)
        self.contratacao_repo.salvar(nova_contratacao)

        # Passo 1.8: Só dispara notificação externa APÓS persistir com sucesso!
        self.notificador.notificar(destinatario=servico.prestador_id, ...)
        return nova_contratacao

4.2 ConsultarServicosUseCase & ConsultarContratacoesUseCase

Implementam as consultas (Queries) exigidas na Seção 7 do PDF:

  • ConsultarServicosUseCase.executar(apenas_com_slots_livres=True): busca os serviços no ServicoRepository e, quando o filtro está ativo, retorna apenas aqueles onde len(s.obter_slots_livres()) > 0.
  • ConsultarContratacoesUseCase.executar(usuario_id): lista o histórico de contratações de um membro (como solicitante ou prestador).

4.3 ConcluirEAvaliarUseCase

Orquestra o fechamento do ciclo de vida do contrato (RF06 e RF07):

  • concluir(contratacao_id, usuario_id): recupera a contratação do repositório, chama contratacao.concluir(usuario_id) no domínio, salva o novo status CONCLUIDA e dispara e-mail avisando o solicitante que ele já pode avaliar.
  • avaliar(contratacao_id, nota, comentario, solicitante_id): recupera a contratação, delega a criação da avaliação para contratacao.registrar_avaliacao(...) (Creator GRASP) e persiste no repositório.

5. Adaptadores Secundários (src/adapters/outbound/)

Pure Fabrication (GRASP) • LSP & DIP (SOLID)

5.1 notificadores.py Seção 8 / ASR-01

Contém duas classes que herdam de NotificadorPort:

  • EmailNotificador: Simula o despacho via servidor SMTP institucional ([SMTP:smtp.ufpr.br] Para: ...).
  • NotificadorFake: Test Double (Spy) que guarda cada mensagem enviada numa lista em memória (self.mensagens_enviadas). Permite que os testes automatizados façam assert len(notificador.mensagens_enviadas) == 1 sem precisar de rede!

5.2 memoria_repositorios.py ASR-03 (Testes < 1s)

Implementa InMemoryServicoRepository e InMemoryContratacaoRepository usando dicionários Python (self.servicos = {}).

Por que existe? Graças ao Princípio da Substituição de Liskov (LSP), podemos injetar esses repositórios em memória nos testes unitários para testar 100% das regras de negócio em milissegundos sem tocar no disco!

5.3 sqlite_repositorios.py ASR-02 (ACID SQLite)

Implementa a persistência relacional real com a biblioteca nativa sqlite3 (4 tabelas: servicos, slots, contratacoes, avaliacoes):

  • Atomicidade (with self.conn:): Abre transação SQLite que faz COMMIT automático no fim do bloco ou ROLLBACK se houver falha.
  • Padrão Data Mapper (ADR-002): Os métodos privados _reconstruir_servico() e _reconstruir_contratacao() convertem as linhas SQL de volta para os objetos puros do Domínio.

Controller (GRASP) • Composition Root

6.1 cli_controller.py

Implementa o MarketplaceController (Adaptador Primário de Terminal). Ele recebe os 3 Casos de Uso no construtor, chama os métodos de aplicação e envolve as chamadas em blocos try / except ErroDominio para exibir mensagens amigáveis no terminal sem deixar o programa quebrar com stacktrace.

6.2 web_controller.py

Segundo Adaptador Primário (Interface Gráfica Web em http://localhost:8000 usando http.server nativo).

Por que é importante na defesa? Prova na prática a Análise de Evolução (Seção 9): adicionamos uma interface Web inteira com API JSON consumindo os mesmos Casos de Uso e o mesmo SQLite sem mudar 1 linha do Domínio!

6.3 src/main.py (Composition Root)

É o único arquivo do sistema que conhece todas as classes concretas ao mesmo tempo para "ligar os fios" (Injeção de Dependência):

  • python -m src.main → Roda os 8 passos da fatia vertical no terminal e grava em campushub.db.
  • python -m src.main --web → Sobe o Front-end Web interativo na porta 8000.
